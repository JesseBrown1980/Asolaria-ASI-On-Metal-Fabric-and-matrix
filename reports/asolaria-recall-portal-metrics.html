Transport finding — keep-alive + tuple text is the measured lever

Measured facts: Acer Rust ran the million-call stress with connection: close (1,353 q/s, 41.35 ms median). Liris ran its local million-call stress with keep-alive (2,928.82 q/s, 19.65 ms median). Acer then applied keep-alive plus .hbp tuple-text and measured 4,220 q/s, 14.43 ms median, 0 JSON responses. Migration posture remains additive: new Rust test-port cell measured, old serving system remains live, any swap stays gated.

Method / reproducibility · honest scope

Bench: loopback http.get + process.hrtime, 20-query warmup, K=60/query, then 500 sequential + 1000×32-concurrent, then health-under-flood, then L0 PII probes. Engine: recall-serve release build, Rust 1.81, run on 127.0.0.1:4796. Receipt + exact bench: METRICS-2026-06-23.md (PR #8).

Scope: single 4-core i5, localhost loopback — not a datacenter, not LAN-RTT (cross-colony adds network). Corpus is acer's ASOLARIA-ACER-RECALL (591k), not published.
